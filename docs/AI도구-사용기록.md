## 2. 주요 문제 해결 과정 4건

### 사례 1 — Git 잠금 파일 오류

| | |
|---|---|
| 상황 | `fatal: Unable to create '.git/index.lock': File exists.` |
| 물어본 것 | 이 메시지가 무슨 뜻이고 무엇을 해야 하는지 |
| 받은 설명 | Git이 작업 중 걸어두는 잠금 파일이 남은 상태. 파일 크기가 0바이트이면 진행 중인 작업이 없다는 뜻 |
| **직접 판단** | 다른 Git 창을 켜둔 것이 없음을 확인한 뒤 삭제 결정 |
| 해결 | `Remove-Item .git\index.lock` 후 재시도 |

> **배운 것**: `fatal` 이라고 해서 모두 심각한 것은 아니다. 메시지가 말하는 상태를 확인하면 판단할 수 있다.

---

### 사례 2 — 배포 실패 (Python entrypoint)

| | |
|---|---|
| 상황 | `Error: No python entrypoint found in default locations, but found: api/design.py (variable: handler)` |
| 물어본 것 | 로그 화면을 보여주며 원인 |
| 받은 설명 | Vercel이 프로젝트를 "Python 웹 애플리케이션"으로 오인. 우리가 만든 것은 서버리스 함수 |
| **직접 판단** | 대시보드에서 설정을 찾지 못해, **설정을 코드 파일로 남기는 방식**을 선택 |
| 해결 | `vercel.json` 에 `"framework": null` 추가 |

> **판단 근거**: 대시보드 설정은 저장소를 받아간 사람에게 전달되지 않는다.
> 코드에 두면 누가 받아가도 똑같이 동작한다. 과제 평가 기준의 "재현 가능"에도 부합한다.

**증빙**: `19_배포실패_preset.png` → `31_AI로그_배포해결.png`

### 사례 3 — AI 호출 404 (가장 중요)

| | |
|---|---|
| 상황 | 화면은 정상, AI만 실패. 사용자에게는 "설계에 실패했어요"만 표시 |
| **직접 한 것** | Vercel 로그를 열어 서버 기록 확인 → `AI 응답 오류: 404` 발견 |
| 받은 설명 | 키가 잘못됐다면 404가 아니라 400/403이 온다. 키는 유효하고 **모델 이름만** 문제 |
| 1차 해결 | 후보 이름 5개를 순차 시도하도록 수정 |
| 결과 | **5개 모두 실패** — 화면의 모델 목록을 보니 3.x 세대였고 후보는 2.x 세대 |
| **직접 판단** | 후보를 더 늘리는 것도 결국 짐작이다. 6번째 이름이 나오면 또 막힌다 |
| 최종 해결 | **사용 가능한 모델 목록을 조회한 뒤 그중에서 선택**하도록 변경 |

```python
def pick_model(api_key):
    response = requests.get(BASE_URL + "/models", ...)   # 목록을 물어본다
    usable = [generateContent 를 지원하는 모델만]
    usable.sort(key=score)                               # flash 우선, preview 후순위
    return usable[0]
```

> **이 사례가 보여주는 것**:
> AI가 제시한 1차 해결책(후보 목록)을 적용했지만 실패했고,
> **그 방식 자체가 짐작에 의존한다는 점**을 파악해 근본 해결로 방향을 바꿨습니다.
> 전화번호를 외워서 거는 방식에서 전화번호부를 먼저 받는 방식으로 바꾼 것입니다.

**증빙**: `21_502_로그.png` → `32_AI로그_모델404.png`

## 3. AI가 만든 코드를 그대로 쓰지 않은 지점

### ① AI 응답을 신뢰하지 않는 방어 코드

AI에게 "JSON만 출력하라"고 지시했지만, 지시를 어길 가능성을 전제로 처리했습니다.

```python
def extract_json(text):
    if text.startswith("```"):        # 코드블록 표시가 붙어 온 경우
        text = text.split("```")[1]
    start = text.find("{")            # 중괄호 구간만 잘라냄
    end = text.rfind("}")
    return json.loads(text[start:end + 1])
```

### ② 재시도 여부를 상태 코드별로 구분

무조건 재시도하면 시간과 쿼터를 낭비합니다.

| 코드 | 뜻 | 재시도 |
|---|---|---|
| 404 | 그런 이름 없음 | ✅ 다른 이름으로 |
| 400 / 403 / 429 | 형식·권한·한도 문제 | ❌ 반복해도 같은 결과 |

### ③ 지원하지 않는 브라우저에서 버튼을 만들지 않음

음성 입력은 Firefox에서 동작하지 않습니다.
오류 메시지를 띄우는 대신 **버튼 자체를 생성하지 않도록** 했습니다.
눌러도 반응 없는 버튼은 "고장났나?"라는 오해를 만들기 때문입니다.

## 4. AI 도구를 쓰면서 지킨 원칙

| 원칙 | 실천 |
|---|---|
| **git 명령어는 직접 친다** | 20개 커밋 전부 직접 입력. 각 명령의 뜻을 확인하고 실행 |
| **동작은 직접 확인한다** | 코드를 받은 뒤 반드시 브라우저에서 눌러보고 다음 단계로 |
| **오류는 로그부터 본다** | 추측하지 않고 Vercel 로그에서 실제 메시지를 확인 |
| **키는 직접 등록한다** | API 키는 AI에게 보여주지 않고 Vercel 설정 화면에만 입력 |
| **한 번에 한 기능씩 커밋** | 문제가 생기면 직전 지점으로 되돌릴 수 있도록 |
