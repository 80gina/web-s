# 수업 설계소

> 요리교실 강사를 위한 AI 커리큘럼 설계 도구

수강생 조건 몇 가지를 입력하면 그날 수업의 **진행표 · 준비물 · 강사 멘트**를 AI가 한 번에 만들어 줍니다.

**🔗 배포 주소 → https://web-s-one.vercel.app**

---

## 1. 서비스 소개

### 왜 만들었나

소규모 요리교실은 대부분 강사 한 사람이 혼자 운영합니다.
그런데 수업 하나를 여는 데 필요한 준비는 매번 처음부터 다시 계산해야 합니다.

- 오늘 오는 수강생이 몇 명이고 나이대가 어떤지에 따라 진행 속도가 달라진다
- 90분과 120분은 같은 요리를 가르쳐도 구성이 완전히 다르다
- 재료를 몇 인분 준비할지, 도구가 몇 세트 필요한지 매번 다시 센다
- 처음 오는 사람이 섞여 있으면 어느 지점에 설명을 끼워야 할지 판단해야 한다

**반복되는 계산인데 자동화되어 있지 않습니다.** 이 서비스는 그 반복을 대신합니다.

### 타겟 사용자

| 항목 | 내용 |
|---|---|
| 주 타겟 | 소규모 요리교실을 혼자 운영하는 강사 (1회 4~12명) |
| 보조 타겟 | 문화센터·주민센터 단발성 요리 강좌 진행자 |
| 사용 순간 | 수업 전날 밤 또는 당일 아침, 장 보러 가기 직전 |

### 화면 구성 (5개 섹션)

| 섹션 | 역할 |
|---|---|
| 메인 | 서비스가 무엇인지 3초 안에 전달 |
| **수업 설계** | 핵심 기능 — 조건 입력 → AI 진행표 생성 |
| 내 보관함 | 만든 설계를 다시 꺼내 봄 |
| 운영 가이드 | 사용법과 자주 묻는 질문 |
| 문의 | 의견·개선 요청 접수 |

단일 페이지(`index.html`) + 앵커 이동 방식이며, 768px 이하에서는 햄버거 메뉴로 전환됩니다.

## 2. AI 기능

### 입력

| 항목 | 형식 | 필수 |
|---|---|---|
| 수강생 인원 | 숫자 (1~30) | ✅ |
| 연령대 | 선택 (초등학생 / 청소년 / 성인 / 시니어 / 혼합) | ✅ |
| 수업 시간 | 선택 (60 / 90 / 120 / 180분) | ✅ |
| 요리 경험 | 선택 (처음 / 조금 / 익숙) | ✅ |
| 만들 음식 | 텍스트 | ✅ |
| 특이사항 | 텍스트 (최대 300자) | ❌ |

### 출력

AI는 문장이 아니라 **데이터(JSON)** 로 응답하고, 화면은 그 데이터를 받아 JavaScript가 직접 그립니다.

- 수업 제목과 한 줄 요약
- **진행표** — 시각 / 소요 시간 / 활동 / 강사 멘트
- **재료 목록** — 인원 기준으로 계산된 수량
- **도구 목록** — 조 편성을 고려한 개수
- 주의할 점
- 시간 배분 코멘트

> 문장이 아닌 데이터로 받는 이유: 완성된 문장을 받으면 화면에 그대로 붙일 수밖에 없습니다.
> 데이터로 받으면 표로도, 카드로도, PDF로도 그릴 수 있어 **화면 구성의 주도권이 이쪽에 남습니다.**

### 실패 처리 (3종 전부 구현)

| 상황 | 판단 기준 | 사용자에게 보이는 것 |
|---|---|---|
| **빈 입력** | 필수값이 비었거나 공백만 있음 | 해당 칸이 빨갛게 표시 + "만들 음식을 입력해 주세요" |
| **API 오류** | 응답 상태가 4xx / 5xx | "설계에 실패했어요. 잠시 후 다시 시도해 주세요." + 다시 시도 버튼 |
| **지연 / 타임아웃** | 20초 경과 → 안내<br>30초 경과 → 중단 | "시간이 조금 걸리고 있어요."<br>"응답이 너무 늦어 중단했습니다." |

빈 입력은 **서버로 보내지 않고 화면에서 먼저 걸러냅니다.** 즉시 알려줄 수 있고, 빈 요청에 AI 호출 비용을 쓰지 않기 위해서입니다.

## 3. 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | HTML5, CSS3, 순수 JavaScript (프레임워크 미사용) |
| 반응형 | CSS 미디어 쿼리 (1024px / 768px / 400px), Flexbox, Grid |
| 백엔드 | Vercel Serverless Functions (Python) |
| AI | Google Gemini API (`generateContent`) |
| HTTP 클라이언트 | `requests` |
| 배포 | Vercel (GitHub 연동 자동 배포) |
| 버전 관리 | Git, GitHub |

### 폴더 구조

```
web-s/
├── index.html              메인 페이지 (5개 섹션)
├── vercel.json             배포 설정 (프레임워크 자동 감지 해제)
├── requirements.txt        Python 패키지 목록
├── css/
│   └── style.css           색 변수 · 레이아웃 · 반응형 · 폼 · 결과 표
├── js/
│   └── main.js             네비게이션 · 입력 검사 · fetch 호출 · 결과 렌더링
├── api/
│   └── design.py           AI 호출 서버리스 함수
└── docs/
    └── 서비스-기획서.md
```

### 데이터가 흐르는 순서

```
사용자가 폼 입력
      ↓
JS가 빈 값 검사 (빈 값이면 여기서 중단 — 서버로 안 보냄)
      ↓
fetch('/api/design') 로 POST 전송
      ↓
Vercel이 Python 서버리스 함수를 깨움
      ↓
환경 변수에서 API 키를 꺼냄
      ↓
쓸 수 있는 모델 목록을 조회해 flash 계열 선택
      ↓
Gemini 호출 → JSON 응답
      ↓
JS가 받아서 진행표를 그림
```

## 4. 실행 방법

### 로컬에서 화면만 확인하기

```bash
git clone https://github.com/80gina/web-s.git
cd web-s
```

`index.html` 을 브라우저로 열면 화면·네비게이션·반응형·빈 입력 검사까지 확인할 수 있습니다.

> ⚠️ **AI 기능은 로컬에서 동작하지 않습니다.**
> `api/design.py` 는 Vercel 환경에서만 실행되기 때문입니다.
> 로컬에서 설계 버튼을 누르면 "연결에 문제가 있었어요" 안내가 표시되며, 이는 실패 처리가 정상 작동한 결과입니다.

| | 로컬 | 배포 |
|---|---|---|
| HTML / CSS / JS | ✅ | ✅ |
| `api/design.py` | ❌ | ✅ |
| 환경 변수 | ❌ | ✅ |

### 전체 기능 확인하기

배포 주소에서 확인합니다 → **https://web-s-one.vercel.app**

## 5. 배포 방법

### 1) GitHub 저장소 준비

```bash
git add .
git commit -m "커밋 메시지"
git push
```

### 2) Vercel 연결

1. https://vercel.com/new 접속
2. `Continue with GitHub` → 저장소 접근 허용
3. 목록에서 저장소를 찾아 **Import**
4. 환경 변수 등록 (아래 6절)
5. **Deploy**

이후에는 `git push` 할 때마다 **자동으로 재배포**됩니다.

### 3) `vercel.json` 이 필요한 이유

```json
{
  "framework": null
}
```

이 파일이 없으면 Vercel이 프로젝트를 **"파이썬 웹 애플리케이션"** 으로 오인해 다음 오류로 빌드가 실패합니다.

```
Error: No python entrypoint found in default locations
```

`"framework": null` 은 자동 감지를 끄고, `api/` 폴더의 파일들을 **각각 서버리스 함수로** 다루게 합니다.
대시보드에서 Preset을 `Other` 로 바꿔도 같은 효과지만, **설정을 코드에 두면 저장소를 받아간 사람도 똑같이 동작**하므로 이 방식을 택했습니다.

## 6. 환경 변수 설정

### 필요한 값

| 이름 | 용도 | 발급처 |
|---|---|---|
| `GEMINI_API_KEY` | Gemini API 호출 인증 | https://aistudio.google.com/apikey |

### Vercel에 등록하는 방법

1. 프로젝트 → **Settings** → **Environment Variables**
2. **Key** 에 `GEMINI_API_KEY` 입력 (대문자·밑줄까지 정확히)
3. **Value** 에 발급받은 키 입력
4. 적용 범위를 **Production and Preview** 로 두고 **Save**
5. **Deployments** 탭 → 최신 배포 `⋯` → **Redeploy**

> 환경 변수는 **배포 시점에 주입**됩니다. 값을 바꾼 뒤에는 반드시 재배포해야 반영됩니다.

### 왜 코드에 직접 적지 않는가

| | 코드에 적으면 | 환경 변수에 두면 |
|---|---|---|
| GitHub (Public) | **누구나 볼 수 있음** | 보이지 않음 |
| 키 유출 시 | 남이 쓴 요금이 나에게 청구됨 | — |
| 키 교체 | 코드 수정 + 재배포 | 설정 화면에서 값만 교체 |

코드에는 아래 한 줄만 있습니다. **키 값 자체는 저장소 어디에도 없습니다.**

```python
api_key = os.environ.get("GEMINI_API_KEY")
```

`.gitignore` 첫 줄에 `.env` 를 넣어 둔 것도 같은 대비입니다.
저장소를 만들기 **전에** 넣었는데, 한 번 올라간 기록은 파일을 지워도 이력에 남기 때문입니다.

## 7. 모델 이름을 코드에 박지 않은 이유

개발 중 다음 오류를 만났습니다.

```
AI 응답 오류: 404   (models/gemini-2.5-flash is not found)
```

모델 이름은 **계정·발급 시기·지역에 따라 다르고, 제공사가 수시로 바꿉니다.**
이름을 하나 박아두면 그 이름이 사라지는 순간 서비스가 멈춥니다.

그래서 호출 직전에 **사용 가능한 모델 목록을 조회한 뒤 그중에서 고르도록** 바꿨습니다.

```python
def pick_model(api_key):
    response = requests.get(BASE_URL + "/models", ...)   # 목록 조회
    usable = [generateContent 를 지원하는 모델만]          # 걸러내기
    usable.sort(key=score)                               # 우선순위 정렬
    return usable[0]
```

선택 기준:

| 기준 | 이유 |
|---|---|
| `flash` 계열 우대 | 20초 안에 응답이 와야 함. 저렴하기도 함 |
| `preview` · `exp` 후순위 | 예고 없이 사라지거나 동작이 바뀔 수 있음 |
| `image` · `tts` · `thinking` 제외 | 용도가 다른 모델 |

한 번 알아낸 이름은 기억해 두어 매 요청마다 목록을 다시 조회하지 않습니다.

## 8. 개발 과정에서 만난 문제와 해결

| # | 문제 | 원인 | 해결 |
|---|---|---|---|
| 1 | `fatal: Unable to create index.lock` | 이전 Git 작업이 잠금 파일을 남김 | 잠금 파일 삭제 후 재시도 |
| 2 | GitHub 권한 화면에서 오류 페이지 | GitHub 측 일시 장애 | 시간을 두고 재시도 |
| 3 | `No python entrypoint found` | Vercel이 Python 앱으로 오인 | `vercel.json` 에 `"framework": null` 추가 |
| 4 | AI 호출 404 | 코드에 적어둔 모델 이름이 존재하지 않음 | 모델 목록 조회 후 자동 선택으로 변경 |

**모두 코드 로직이 아니라 환경·설정·외부 서비스 문제였습니다.**
문제를 좁혀 들어갈 수 있었던 것은 오류를 두 갈래로 나눠 두었기 때문입니다.

```python
print("AI 응답 오류:", model, response.status_code, response.text[:500])   # 서버 로그에만
self._send(502, {"error": "설계에 실패했어요. 잠시 후 다시 시도해 주세요."})    # 사용자에게
```

사용자는 `500 Internal Server Error` 를 봐도 할 수 있는 일이 없습니다.
**사용자에게는 다음에 할 행동을, 개발자에게는 진짜 원인을** 전달합니다.
