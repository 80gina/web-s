## 1. HTML/CSS/JavaScript가 각각 어떤 역할을 하는지 설명할 수 있다

### 세 가지는 겹쳐서 하나의 화면을 만듭니다

| | 역할 | 비유 | 없으면 |
|---|---|---|---|
| **HTML** | 뼈대와 내용 | 건물의 골조와 방 배치 | 아무것도 없음 |
| **CSS** | 보기 좋게 꾸미기 | 벽지·조명·가구 배치 | 못생겼지만 작동은 함 |
| **JavaScript** | 움직이게 하기 | 전등 스위치·자동문 | 예쁘지만 반응이 없음 |

### 직접 확인한 방법 — 순서대로 하나씩 붙였습니다

일부러 세 단계로 나누어 커밋했고, 각 단계마다 화면을 확인했습니다.

| 커밋 | 붙인 것 | 그때 화면 |
|---|---|---|
| `a4f5056` | HTML만 | 검은 글씨만 빽빽한 하얀 화면. 내용은 다 있으나 배치·색이 없음 |
| `223298c` | CSS 추가 | 아이보리 배경, 고정 헤더, 주황 버튼. **내용은 그대로인데 모양만 바뀜** |
| `1d93ebf` | JavaScript 추가 | 햄버거 메뉴가 **눌러서 열림**. 현재 섹션이 메뉴에 표시됨 |

> 증빙: 스크린샷 `08_html_only.png` 와 `09_css_적용후.png` 를 나란히 보면 CSS의 역할이 한눈에 보입니다.

### 이 서비스에서 각각이 맡은 구체적인 일

**HTML (`index.html`, 187줄)**

```html
<section id="design">
  <h2>수업 설계</h2>
  <input type="number" id="headcount">
</section>
```

- 5개 섹션의 구획과 순서
- 입력칸이 몇 개이고 각각 무엇을 받는지
- `id` 로 이름표를 붙여 CSS와 JS가 찾아올 수 있게 함

**CSS (`css/style.css`, 735줄)**

```css
#navMenu { display: none; }          /* 모바일에서 평소엔 숨김 */
#navMenu.open { display: flex; }     /* open 이름표가 붙으면 보임 */
```

- 색·글꼴·여백·배치
- 화면 크기별 레이아웃 (미디어 쿼리 3개)
- **"어떤 상태일 때 어떻게 보일지"** 를 미리 정의

**JavaScript (`js/main.js`, 419줄)**

```javascript
menuToggle.addEventListener("click", function () {
  navMenu.classList.toggle("open");
});
```

- 클릭·입력 같은 사건에 반응
- 입력값 검사
- 서버에 요청을 보내고 받은 데이터로 화면을 그림

### 가장 중요한 지점 — JavaScript는 메뉴를 직접 보이게 하지 않습니다

위 코드에서 JavaScript가 하는 일은 **`open` 이라는 이름표를 붙였다 뗐다** 하는 것뿐입니다.
실제로 메뉴를 보이게 만드는 것은 **CSS** 입니다.

> JavaScript는 **전등 스위치를 누르는 손**, CSS는 **전선과 전구**입니다. 손이 빛을 내는 게 아닙니다.

이 분담 덕분에, 나중에 메뉴 디자인을 바꾸고 싶으면 **CSS만 고치면 되고 JavaScript는 손대지 않아도 됩니다.**

### 📋 요약

| 질문 | 답 |
|---|---|
| HTML은? | 뼈대와 내용. 무엇이 어떤 순서로 있는지 |
| CSS는? | 모양. 색·배치·화면 크기별 대응 |
| JavaScript는? | 동작. 사건에 반응하고 데이터를 화면에 반영 |
| 셋이 협업하는 예 | JS가 `open` 클래스를 붙이면 → CSS가 메뉴를 보이게 함 |
| 확인한 방법 | HTML → CSS → JS 순서로 커밋하며 화면 변화를 직접 관찰 |

## 2. 사용자 입력이 JavaScript를 통해 요청(fetch)으로 바뀌고, 응답이 화면에 반영되는 흐름을 설명할 수 있다

### 전체 흐름 8단계

```
① 사용자가 폼에 조건 입력
② JS가 빈 값 검사            (빈 값이면 여기서 중단 — 서버로 안 감)
③ 값을 JSON 문자열로 변환
④ fetch('/api/design') 로 POST 전송
⑤ Python 함수가 AI 호출
⑥ JSON 응답을 받음
⑦ JS가 응답을 자바스크립트 값으로 변환
⑧ 반복문을 돌며 표를 그림
```

### ② 검사 — 서버로 보내기 전에 거릅니다

```javascript
if (el.value.trim() === "") {
  showError(field.message, el);
  return null;              // 여기서 멈춤
}
```

`trim()` 은 앞뒤 공백을 없앱니다. **이게 없으면 스페이스바만 눌러도 통과**해서, 사용자는 아무것도 안 적었는데 AI 호출 비용이 발생합니다.

### ④ 전송 — fetch가 하는 일

```javascript
const response = await fetch("/api/design", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(data),
  signal: controller.signal
});
```

| 조각 | 뜻 |
|---|---|
| `fetch("/api/design")` | 그 주소로 요청을 보내라 |
| `method: "POST"` | 값을 실어 보내는 방식으로 |
| `JSON.stringify(data)` | 자바스크립트 값을 전송 가능한 글자로 변환 |
| `await` | **답이 올 때까지 기다려라** |
| `signal` | 필요하면 도중에 취소할 수 있게 |

`await` 가 없으면 **답이 오기도 전에 다음 줄이 실행**되어 빈 결과를 그리게 됩니다.

### 폼 기본 동작을 막아야 하는 이유

```javascript
designForm.addEventListener("submit", function (event) {
  event.preventDefault();
  ...
});
```

원래 HTML 폼은 제출하면 **페이지를 통째로 새로고침**합니다. 그러면 입력값이 사라지고 화면이 껌뻑입니다.
`preventDefault()` 로 그 기본 동작을 막고, **대신 우리가 정한 일**(검사 → 호출 → 렌더링)을 합니다.

### ⑧ 렌더링 — 데이터를 표로 그립니다

```javascript
data.timetable.forEach(function (row) {
  html += "<tr>";
  html += "<td>" + escapeHtml(row.time) + "</td>";
  html += "<td>" + escapeHtml(row.duration) + "분</td>";
  ...
});
resultBox.innerHTML = html;
```

AI가 **문장이 아니라 데이터**를 주기 때문에 가능한 일입니다.
같은 데이터로 표 대신 카드로도, PDF로도 그릴 수 있습니다. **화면 구성의 주도권이 이쪽에 있습니다.**

### `escapeHtml` 을 거치는 이유

AI 응답이나 사용자 입력에 `<` `>` 같은 기호가 섞이면 화면 구조가 깨질 수 있습니다.
기호를 글자로 바꿔 넣어 그 가능성을 차단했습니다.

### 📋 요약

| 질문 | 답 |
|---|---|
| 입력이 요청이 되는 지점 | `JSON.stringify(data)` → `fetch(..., {body})` |
| `await` 가 필요한 이유 | 답이 오기 전에 다음 줄이 실행되는 것을 막기 위해 |
| `preventDefault()` 가 필요한 이유 | 폼 기본 동작(새로고침)을 막고 우리가 정한 일을 하기 위해 |
| 응답이 화면이 되는 지점 | `forEach` 로 반복하며 `innerHTML` 에 표를 조립 |
| 검사를 화면에서 먼저 하는 이유 | 즉시 안내 + 빈 요청에 비용을 쓰지 않기 위해 |

## 3. Vercel Serverless Functions가 무엇이고, 프론트에서 백엔드(Python)를 호출하는 구조를 설명할 수 있다

### 서버리스 함수란

**요청이 올 때만 잠깐 켜지는 작은 프로그램**입니다.

| | 일반 서버 | 서버리스 |
|---|---|---|
| 켜져 있는 시간 | 24시간 계속 | 요청이 올 때만 몇 초 |
| 비용 | 안 써도 나감 | 쓴 만큼만 |
| 관리 | 직접 | 플랫폼이 대신 |

> 비유: 24시간 여는 식당이 아니라, **벨을 누르면 작동하는 자판기**입니다.

### 폴더 구조가 곧 주소가 됩니다

```
api/design.py   →   https://web-s-one.vercel.app/api/design
```

`api/` 폴더에 파일을 두는 것만으로 주소가 생깁니다. 라우팅 설정을 따로 쓰지 않았습니다.

### Vercel이 찾는 것 — `handler`

```python
class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        ...
    def do_GET(self):
        self._send(405, {"error": "이 주소는 POST 방식으로만 사용할 수 있습니다."})
```

Vercel은 `handler` 라는 이름의 클래스를 찾아 실행합니다.
`do_POST` 는 값을 실어 보낸 요청을, `do_GET` 은 주소창으로 직접 들어온 경우를 처리합니다.

> **검증**: 배포 후 브라우저로 `/api/design` 에 직접 접속하면 405와 위 안내 문구가 나옵니다.
> 404가 아니라 405가 나온다는 것은 **함수가 실제로 배포되어 실행되고 있다**는 증거입니다.

### 왜 굳이 Python을 중간에 두는가 — 이 구조의 핵심 이유

```
❌ 브라우저 JS → AI 직접 호출
   → 키를 JS 파일에 적어야 함
   → 누구나 "페이지 소스 보기"로 키를 볼 수 있음

✅ 브라우저 JS → Python 함수 → AI
                 (키는 여기에만 있음)
```

브라우저는 키를 모른 채 "설계해 줘"라고만 요청하고, **키를 아는 Python이 대신** AI에게 갑니다.

> 비유: 금고 비밀번호를 손님에게 알려주지 않고, **직원이 대신 금고를 열어 물건을 꺼내다 주는 것**입니다.

### 배포 설정 — `vercel.json` 이 필요했던 이유

첫 배포는 실패했습니다.

```
Error: No python entrypoint found in default locations, but found:
  api/design.py (variable: handler)
```

Vercel이 프로젝트를 **"파이썬 웹 애플리케이션"** 으로 오인해 프로그램 시작점을 찾은 것입니다.
우리가 만든 것은 애플리케이션이 아니라 **서버리스 함수**입니다.

```json
{ "framework": null }
```

이 한 줄로 자동 감지를 끄자 빌드가 통과했습니다.
대시보드에서 Preset을 `Other` 로 바꿔도 같은 효과지만, **설정을 코드에 두면 저장소를 받아간 사람도 똑같이 동작**하므로 파일로 남겼습니다.

### 📋 요약

| 질문 | 답 |
|---|---|
| 서버리스 함수란 | 요청이 올 때만 잠깐 켜지는 프로그램. 쓴 만큼만 과금 |
| 주소는 어떻게 정해지나 | `api/design.py` → `/api/design`. 폴더 구조가 곧 주소 |
| Vercel이 찾는 이름 | `handler` 클래스. `do_POST` / `do_GET` 으로 방식 구분 |
| 왜 Python을 거치나 | **API 키를 브라우저에 노출하지 않기 위해** |
| `vercel.json` 이 필요했던 이유 | Vercel이 Python 앱으로 오인 → `"framework": null` 로 자동 감지 해제 |
| 함수가 살아있는지 확인법 | `/api/design` 직접 접속 시 404가 아닌 **405** 가 오면 정상 |

## 4. 환경 변수로 API 키를 안전하게 관리해야 하는 이유를 설명할 수 있다

### 코드에 키를 적으면 벌어지는 일

이 저장소는 **Public** 입니다. 과제 평가 기준에 *"동료가 접속/테스트 가능해야 한다"* 가 있기 때문입니다.

| | 코드에 적으면 | 환경 변수에 두면 |
|---|---|---|
| GitHub에서 | **누구나 볼 수 있음** | 보이지 않음 |
| 키 유출 시 | 남이 내 키로 AI를 쓰고 **요금은 나에게 청구** | — |
| 키 교체 | 코드 수정 + 커밋 + 재배포 | 설정 화면에서 값만 교체 |
| 협업 | 키까지 같이 넘어감 | 각자 자기 키를 씀 |

### 코드에는 이 한 줄만 있습니다

```python
api_key = os.environ.get("GEMINI_API_KEY")
```

**"실행 환경에 있는 `GEMINI_API_KEY` 라는 값을 가져와"** 라는 뜻입니다.
키 값 자체는 **저장소 어디에도 없습니다.** 값은 Vercel 설정 화면에만 존재합니다.

### 키가 없을 때도 서비스가 죽지 않게 했습니다

```python
if not api_key:
    self._send(500, {"error": "서버 설정이 완료되지 않았습니다. 잠시 후 다시 시도해 주세요."})
    return
```

키가 비어 있으면 프로그램이 오류로 터지는 대신, **사용자에게 안내를 돌려주고 정상 종료**합니다.

### `.gitignore` 를 저장소 생성 *전에* 만든 이유

```
# 환경 변수 (API 키) — 절대 GitHub에 올라가면 안 됨
.env
.env.local
```

**한 번 올라간 기록은 파일을 지워도 이력에 남습니다.** 커밋 하나만 되돌리면 그 안에 키가 그대로 있습니다.

> 비유: 사진을 찍기 전에 책상 위 지갑을 치우는 것과 같습니다. 찍은 뒤에 치우면 이미 찍힌 사진에는 지갑이 남아 있습니다.

그래서 **첫 커밋(`ae6883c`)에 `.gitignore` 를 포함**시켰습니다. 프로젝트에서 가장 먼저 한 일입니다.

### 실제로 작동했는지 확인한 방법

개발 중 Python 문법 검사를 돌리면서 `api/__pycache__` 폴더가 생겼습니다.
`.gitignore` 에 `__pycache__/` 를 넣어 두었기 때문에 `git status` 목록에 나타나지 않았고, 커밋에도 포함되지 않았습니다.

```
git add .
git commit
 2 files changed, 200 insertions(+)
 create mode 100644 api/design.py
 create mode 100644 requirements.txt        ← __pycache__ 없음
```

### 키가 유출되었다고 의심되면

1. 발급처(Google AI Studio)에서 **해당 키를 즉시 폐기**
2. 새 키를 발급받아 Vercel 환경 변수에 재등록 후 **재배포**
3. 커밋 이력에 키가 섞여 있다면 해당 이력을 정리하거나 **저장소를 새로 생성**

### 📋 요약

| 질문 | 답 |
|---|---|
| 왜 코드에 안 적나 | 저장소가 Public이라 누구나 볼 수 있고, 남이 쓴 요금이 나에게 청구됨 |
| 코드에 남은 것 | `os.environ.get("GEMINI_API_KEY")` — 이름만, 값은 없음 |
| 값은 어디에 | Vercel Settings → Environment Variables |
| `.gitignore` 를 먼저 만든 이유 | 한 번 올라간 기록은 파일을 지워도 이력에 남기 때문 |
| 키가 없을 때 | 프로그램이 터지지 않고 안내 메시지를 반환 |
| 유출 의심 시 | 즉시 폐기 → 재발급 → 재등록 → 재배포 |

## 5. 로컬 환경과 배포 환경의 차이를 이해하고, 배포 후 문제를 수정·재배포하는 흐름을 설명할 수 있다

### 두 환경의 차이

| | 로컬 (내 컴퓨터) | 배포 (Vercel) |
|---|---|---|
| 주소 | `file:///C:/.../index.html` | `https://web-s-one.vercel.app` |
| HTML / CSS / JS | ✅ 동작 | ✅ 동작 |
| `api/design.py` | ❌ 실행 안 됨 | ✅ 실행됨 |
| 환경 변수 | ❌ 없음 | ✅ 주입됨 |
| 접근 가능한 사람 | 나만 | 누구나 |

### 직접 확인한 방법

로컬에서 `index.html` 을 열고 수업 설계를 눌렀을 때:

> **"연결에 문제가 있었어요. 인터넷 상태를 확인하고 다시 시도해 주세요."**

내 컴퓨터에는 `/api/design` 이라는 주소가 없기 때문입니다.
**이것은 오류가 아니라 실패 처리 코드가 정상 작동한 결과입니다.**

배포 주소에서 같은 동작을 하면 진행표가 생성됩니다.

### 수정 → 재배포 흐름

```
① 코드 수정
② git add / commit / push
③ Vercel이 push를 감지해 자동 배포 시작
④ 1~3분 후 Ready
⑤ 배포 주소에서 확인
```

GitHub와 Vercel을 연결할 때 준 **repository hooks 권한**이 ③을 가능하게 합니다.
배포 버튼을 따로 누르지 않습니다.

### ⚠️ 환경 변수는 예외입니다

환경 변수는 **배포 시점에 주입**됩니다. 값을 바꿔도 **이미 배포된 것에는 반영되지 않습니다.**
값 변경 후에는 반드시 `Deployments → ⋯ → Redeploy` 를 해야 합니다.

### 실제로 이 흐름을 4번 돌았습니다

| 배포 | 결과 | 원인 | 수정 |
|---|---|---|---|
| 1차 | ❌ Error | Application Preset이 Python으로 자동 설정 | — |
| 2차 | ❌ Error | 같은 원인 (설정 미변경) | — |
| 3차 | ✅ Ready | — | `vercel.json` 추가 |
| 4차 | ✅ Ready + AI 동작 | AI 404 (모델 이름) | 모델 자동 선택으로 변경 |

**빌드 성공과 기능 동작은 별개**라는 것을 3차에서 배웠습니다.
화면은 정상적으로 떴지만 AI 호출은 실패했고, 원인은 서버 로그에서만 확인할 수 있었습니다.

### 📋 요약

| 질문 | 답 |
|---|---|
| 가장 큰 차이 | 로컬에는 서버리스 함수와 환경 변수가 없음 |
| 로컬에서 AI가 안 되는 이유 | `/api/design` 주소가 내 컴퓨터에 존재하지 않음 |
| 재배포 흐름 | 코드 수정 → push → Vercel 자동 감지 → 빌드 → Ready |
| 자동 배포가 되는 이유 | GitHub 연동 시 부여한 repository hooks 권한 |
| 환경 변수의 예외 | 값 변경 후 **반드시 Redeploy** 해야 반영됨 |
| 배운 것 | 빌드 성공 ≠ 기능 동작. 둘을 따로 확인해야 함 |

## 6. AI 코딩 도구로 코드를 생성하더라도, 오류 원인을 파악하고 수정 방향을 말로 설명할 수 있다

### 오류를 두 갈래로 나눠 두었습니다

```python
print("AI 응답 오류:", model, response.status_code, response.text[:500])   # 서버 로그에만
self._send(502, {"error": "설계에 실패했어요. 잠시 후 다시 시도해 주세요."})    # 사용자에게
```

| 대상 | 받는 정보 | 이유 |
|---|---|---|
| **사용자** | "잠시 후 다시 시도해 주세요" | `500 Internal Server Error` 를 봐도 할 수 있는 일이 없음 |
| **개발자** | 상태 코드 + 응답 원문 + 사용한 모델 이름 | 원인을 좁히려면 사실이 필요함 |

**이 설계 덕분에 아래 문제들을 추측 없이 해결할 수 있었습니다.**

### 사례 1 — `fatal: Unable to create index.lock`

| | |
|---|---|
| 메시지 | "`index.lock` 파일을 만들려는데 이미 있어서 못 만들겠어" |
| 원인 | Git이 작업 중 걸어두는 잠금 파일이 남아 있었음 |
| 판단 근거 | 파일 크기가 **0 바이트** → 진행 중인 작업 없음 |
| 해결 | `Remove-Item .git\index.lock` 후 재시도 |

### 사례 2 — `No python entrypoint found`

| | |
|---|---|
| 메시지 | "파이썬 프로그램 시작점을 못 찾았어. 그런데 `api/design.py` 에 `handler` 는 있네" |
| 원인 | Vercel이 프로젝트를 Python 애플리케이션으로 오인 |
| 판단 근거 | 메시지가 `handler` 를 **찾긴 했다**고 말함 → 파일 문제가 아니라 해석 문제 |
| 해결 | `vercel.json` 에 `"framework": null` 추가 |

### 사례 3 — AI 호출 404

| | |
|---|---|
| 로그 | `AI 응답 오류: 404` |
| 원인 | 코드에 적어둔 `gemini-2.5-flash` 라는 이름이 존재하지 않음 |
| 판단 근거 | 키가 잘못됐다면 404가 아니라 **400 또는 403** 이 옴 → 키는 유효, 이름만 문제 |
| 1차 해결 | 후보 이름 5개를 순차 시도 → **5개 모두 실패** |
| 최종 해결 | **모델 목록을 조회한 뒤 그중에서 선택** |

### 사례 3에서 배운 것 — 짐작을 코드에서 제거했습니다

후보 목록을 늘리는 방식은 **또 다른 짐작**이었습니다. 5개를 더 적어도 6번째 이름이 나오면 다시 막힙니다.

```python
def pick_model(api_key):
    response = requests.get(BASE_URL + "/models", ...)   # 목록을 물어본다
    usable = [generateContent 를 지원하는 모델만]
    usable.sort(key=score)                               # 우선순위로 정렬
    return usable[0]
```

> 전화번호를 외워서 거는 방식에서, **전화번호부를 먼저 받아보고 거는 방식**으로 바꿨습니다.

선택 기준도 이유를 붙여 정했습니다.

| 기준 | 이유 |
|---|---|
| `flash` 계열 우대 | 20초 안에 응답이 와야 하고, 저렴함 |
| `preview` · `exp` 후순위 | 예고 없이 사라지거나 동작이 바뀔 수 있음 |
| `image` · `tts` · `thinking` 제외 | 용도가 다른 모델 |

### 상태 코드를 구분해 다르게 처리했습니다

```python
if response.status_code == 404:
    continue      # 이름 문제 → 다음 후보로
break             # 그 외 → 모델을 바꿔도 소용없으므로 중단
```

| 코드 | 뜻 | 재시도? |
|---|---|---|
| 404 | 그런 이름 없음 | ✅ 다른 이름으로 |
| 400 | 요청 형식 오류 | ❌ 같은 결과 |
| 403 | 권한 없음 | ❌ 5번 더 거절당할 뿐 |
| 429 | 호출 한도 초과 | ❌ 상황을 악화시킴 |

**무조건 재시도하면 시간도 쿼터도 5배로 씁니다.** 과제 제약사항의 *"호출 빈도와 실패 상황을 고려한다"* 에 대한 대응입니다.

### AI가 만든 코드를 그대로 쓰지 않은 지점

AI에게 "JSON만 출력하라"고 지시했지만, 지시를 어길 가능성을 전제로 방어 코드를 넣었습니다.

```python
def extract_json(text):
    if text.startswith("```"):        # 코드블록 표시가 붙어 온 경우
        text = text.split("```")[1]
    start = text.find("{")            # 중괄호 구간만 잘라냄
    end = text.rfind("}")
    return json.loads(text[start:end + 1])
```

**"AI는 지시를 안 지킬 수 있다"** 를 전제로 설계했습니다.

### 📋 요약

| 질문 | 답 |
|---|---|
| 오류 정보를 어떻게 나눴나 | 사용자에겐 다음 행동, 개발자에겐 원인 (서버 로그) |
| 404를 보고 무엇을 판단했나 | 키가 틀렸으면 400/403이 옴 → **키는 유효, 이름만 문제** |
| 후보 목록 방식을 왜 버렸나 | 그것도 짐작이라 6번째 이름이 나오면 또 막힘 |
| 최종 해결 | 모델 목록을 조회해 자동 선택 |
| 재시도 기준을 나눈 이유 | 무조건 재시도하면 시간·쿼터를 5배 쓰고 상황만 악화 |
| AI 응답을 그대로 믿지 않은 부분 | `extract_json` — 코드블록·설명이 섞여 와도 JSON만 추출 |

필수 요구사항이 **배포되어 동작하는 것을 확인한 뒤에** 착수했습니다.
보너스를 먼저 만들다 배포에 실패하면 과제 자체가 성립하지 않기 때문입니다.

| 항목 | 대응 | 커밋 | 핵심 판단 |
|---|---|---|---|
| 보관함 저장 | 보너스 1 (데이터 저장) | 16 | 서버 대신 브라우저 저장 — 로그인·개인정보 책임 회피 |
| PDF 다운로드 | 보너스 1 (운영 흐름 확장) | 17 | 라이브러리 대신 브라우저 인쇄 — 한글 폰트 문제 회피 |
| 음성 입력 | 보너스 2 (UX 고도화) | 18 | 미지원 브라우저에서는 **버튼을 만들지 않음** |
| 캐싱·호출 제한 | 제약사항 (과금·쿼터) | 19 | 메모리 기반 — 한계를 알고 규모에 맞춰 선택 |

### 각 결정의 근거

**보관함을 서버에 두지 않은 이유**
서버에 저장하면 로그인이 필요해지고, 개인정보를 보관하는 책임이 생깁니다.
기획서 1-3절에 "로그인을 만들지 않는다"고 적어 둔 결정과 일관되게 브라우저 저장을 택했습니다.
대신 다른 기기에서 보이지 않는다는 한계를 운영 가이드 FAQ에 명시했습니다.

**PDF에 라이브러리를 쓰지 않은 이유**
PDF 생성 라이브러리는 한글을 쓰려면 폰트 파일을 따로 넣어야 하고, 그 파일만 수 MB입니다.
넣지 않으면 한글이 네모(□□□)로 나옵니다.
브라우저 인쇄 기능은 화면 글꼴을 그대로 쓰므로 이 문제가 없고, 내려받을 파일도 없습니다.

**음성 입력에서 버튼을 조건부로 만든 이유**

| 방식 | 사용자가 겪는 일 |
|---|---|
| 버튼을 만들고 오류 표시 | 눌렀는데 "지원 안 함" → 헛수고 |
| 버튼을 만들고 무반응 | **"고장났나?"** |
| 버튼을 만들지 않음 | 없는 기능을 기다리지 않음 ✓ |

**캐싱의 한계를 감수한 이유**
캐시와 호출 기록은 서버리스 함수의 메모리에 있습니다.
함수가 종료되면 사라지고, 여러 함수가 동시에 돌면 각자 따로 셉니다.
확실한 제한에는 외부 저장소(Redis 등)가 필요하지만, 이 서비스 규모에서는 과한 구성이고
배포 실패 위험만 커집니다. **한계를 알고 선택했으며, 필요해지면 교체할 수 있는 구조입니다.**

### 하지 않은 것

| 항목 | 이유 |
