# 시연 시나리오 — 수업 설계소

> 발표·구술 평가용. **5분 기준**이며, 시간이 짧으면 ★ 표시된 것만 하면 됩니다.

---

| 준비 | 이유 |
|---|---|
| 브라우저 탭 3개를 미리 열어둔다 | 발표 중 주소 치다가 오타 나면 흐름이 끊깁니다 |

| **인터넷 연결 확인** | AI 호출이 안 되면 시연이 무너집니다 |

없으면 그 자리에서 얼어붙습니다.

## 1. 무엇을 만들었는지 (40초) ★

> "요리교실 강사를 위한 **수업 설계소**를 만들었습니다.
>
> 소규모 요리교실은 대부분 강사 한 사람이 혼자 운영합니다. 그런데 수업 하나를 열 때마다 계산을 다시 해야 해요. 오늘 몇 명이 오는지, 몇 살대인지, 시간이 90분인지 120분인지에 따라 구성이 완전히 달라지거든요. 재료를 몇 인분 살지도 매번 다시 셉니다.
>
> **반복되는 계산인데 자동화가 안 되어 있습니다.** 그래서 조건 몇 개만 넣으면 그날의 진행표, 준비물, 강사 멘트를 AI가 한 번에 만들어 주는 서비스를 만들었습니다."

**화면**: 메인 화면 (①번 탭)

## 2. 실제로 동작하는 모습 (90초) ★★ — 가장 중요

**화면**: `수업 설계` 섹션으로 이동

> "실제로 해보겠습니다."

미리 정한 값을 입력합니다.

| 칸 | 값 |
|---|---|
| 수강생 인원 | `8` |
| 연령대 | 성인 |
| 수업 시간 | 120분 |
| 요리 경험 | 처음이에요 |
| 만들 음식 | `잡채와 겉절이` |

### 기다리는 10~20초 동안 말할 것 — 침묵을 채우세요

> "지금 AI를 호출하고 있습니다. 이 사이에 화면 뒤에서 무슨 일이 일어나는지 말씀드리면요 —
> 브라우저의 JavaScript가 입력값을 검사한 다음, `fetch` 로 서버에 보냅니다. 서버에서는 Python 함수가 깨어나서 API 키를 꺼내고 AI를 호출합니다. 응답을 JSON으로 받아서 다시 브라우저로 돌려주면, JavaScript가 그걸 표로 그립니다."

### 결과가 나오면

> "나왔습니다. 여기 보시면 —
> **진행표**가 시각·소요 시간·활동·강사 멘트로 나뉘어 있고, **시각이 소요 시간만큼 정확히 누적**됩니다. 00:00에서 10분이면 다음이 00:10이에요.
>
> 강사 멘트도 보시면 *'여러분 안녕하세요, 오늘 우리는…'* 처럼 **실제로 소리 내어 읽을 수 있는 문장**입니다. AI에게 그렇게 지시했거든요.
>
> 아래로 내리면 재료가 **8명 기준으로 계산**되어 있고, 도구는 몇 명이 한 조인지까지 고려한 개수로 나옵니다."

**스크롤해서 재료·도구·주의사항까지 보여줍니다.**

## 3. 실패했을 때는 어떻게 되나 (40초) ★

> "잘 될 때만 보여드리면 반쪽이니, **실패할 때**도 보여드리겠습니다."

**입력을 모두 비우고 `수업 설계하기` 클릭**

> "빈 상태로 누르면 이렇게 안내가 나오고, 문제가 된 칸으로 커서가 갑니다.
>
> 여기서 중요한 건 — **이 요청은 서버로 가지 않았다**는 점입니다. 화면 단계에서 걸러냈어요.
> 두 가지 이유입니다. 서버를 거치면 1~2초 뒤에야 '비었어요'를 알게 되고, 또 하나는 **AI 호출은 건당 요금이 발생**하기 때문입니다. 빈 요청에까지 돈을 쓸 이유가 없습니다."

> "실패 처리는 세 가지를 만들었습니다. 지금 보신 빈 입력, 그리고 API 오류가 나면 다시 시도 버튼이 나오고, 20초가 지나면 기다려 달라는 안내, 30초가 지나면 중단합니다.
>
> **20초와 30초를 나눈 이유**가 있습니다. 20초에 바로 포기하면 거의 다 온 응답을 버리게 되고, 안내 없이 계속 기다리게 하면 사용자는 멈춘 줄 알고 창을 닫습니다."

## 5. 보안 — API 키를 어떻게 다뤘나 (40초) ★

**화면**: ②번 탭(GitHub) → `api/design.py` 열기

> "이 저장소는 **Public** 입니다. 누구나 코드를 볼 수 있어요.
> 그런데 AI를 호출하려면 API 키가 필요합니다. 코드에 적으면 그 키가 전 세계에 공개됩니다. 남이 제 키로 AI를 쓰면 **요금은 저에게 청구**됩니다."

`api_key = os.environ.get("GEMINI_API_KEY")` 부분을 가리키며 —

> "그래서 코드에는 이 한 줄만 있습니다. **'환경 변수에서 가져와'** 라는 뜻이고, 키 값 자체는 저장소 어디에도 없습니다."

**화면**: ③번 탭(Vercel) → Environment Variables

> "실제 값은 여기에만 있습니다. 이렇게 가려져서 표시되고요."

> "그리고 프로젝트에서 **가장 먼저 한 일**이 `.gitignore` 에 `.env` 를 넣는 거였습니다. 첫 커밋에 들어가 있어요.
> 왜냐하면 **한 번 올라간 기록은 파일을 지워도 이력에 남기** 때문입니다. 커밋 하나만 되돌리면 그 안에 키가 그대로 있어요. 사진 찍기 전에 지갑을 치우는 것과 같습니다."

## 6. 막혔던 지점과 해결 (60초) ★★ — 두 번째로 중요

> "만드는 과정에서 배포가 세 번 실패했습니다. 그중 하나를 말씀드리겠습니다."

### 사례 — AI 호출 404

> "화면은 잘 뜨는데 AI만 계속 실패했습니다. 사용자에게는 '설계에 실패했어요'라고만 보이니까 원인을 알 수 없었죠.
>
> 그런데 제가 코드에 **오류를 두 갈래로 나눠** 뒀습니다. 사용자에게는 부드러운 안내를 주고, 진짜 원인은 서버 로그에만 남기게요.
>
> 로그를 열어보니 **404** 였습니다. '그런 이름의 모델이 없다'는 뜻이에요.
>
> 여기서 판단을 했습니다. **키가 잘못됐다면 404가 아니라 400이나 403이 옵니다.** 그러니까 키는 멀쩡하고 이름만 문제였던 거예요.
>
> 처음엔 후보 이름을 5개 적어서 순서대로 시도하게 고쳤습니다. 그런데 **5개가 다 실패**했어요. 제미나이가 3.x 세대까지 왔는데 제 목록은 2.x 였거든요.
>
> 그래서 방식을 바꿨습니다. **이름을 짐작하지 말고, 쓸 수 있는 모델 목록을 먼저 물어본 다음 그중에서 고르게** 했습니다. 전화번호를 외워서 거는 대신 전화번호부를 먼저 받아보는 거죠.
>
> 지금은 구글이 이름을 뭘로 바꾸든 알아서 따라갑니다."

**이 이야기가 왜 강한가**: 실패 → 1차 해결 → **그것도 짐작이라는 자각** → 근본 해결. 사고 과정이 그대로 보입니다.

## 예상 질문과 답변

### Q. 왜 프레임워크를 안 썼나요?

> "과제 조건이기도 하지만, 5개 섹션 규모에는 과한 도구라고 봤습니다.
> 그리고 프레임워크를 쓰면 **HTML·CSS·JavaScript가 각각 뭘 하는지 배우기 어려워집니다.** 저는 이번에 그걸 익히는 게 목적이었어요.
> 실제로 HTML만 있는 화면 → CSS 추가 → JavaScript 추가 순서로 커밋하면서 각 단계 화면을 확인했습니다."

### Q. AI가 이상한 답을 주면 어떡하나요?

> "두 가지로 대비했습니다.
> 첫째, AI에게 **JSON 형식으로만 답하라고 설정으로 강제**했습니다. 말로 부탁하는 게 아니라 API 옵션으로요.
> 둘째, 그래도 앞뒤에 설명이 붙어 올 수 있으니 **중괄호 구간만 잘라내는 코드**를 넣었습니다.
> 그리고 받은 데이터가 예상한 모양인지 화면에서 한 번 더 검사합니다. 진행표가 배열이 아니면 오류 안내로 처리해요."

### Q. 비용은 어떻게 관리하나요?

> "네 가지를 했습니다.
> 빈 입력은 서버로 안 보냅니다. 요청 중에는 버튼을 잠가서 연속 클릭을 막습니다. 모델은 빠르고 저렴한 flash 계열을 우선 고르게 했고요. 30초가 지나면 요청 자체를 취소합니다."

### Q. 이 서비스를 실제로 쓸 건가요?

> "네. 제가 요리교실을 운영하면서 겪은 불편이라 타겟이 곧 저 자신입니다.
> 다만 지금은 결과를 저장하는 기능이 브라우저 안에만 있어서, 다른 기기에서는 안 보입니다. 다음 단계로 PDF 다운로드와 음성 입력을 붙일 계획입니다.
> **음성 입력은 이유가 있습니다.** 강사는 수업 준비 중에 손이 젖어 있거나 짐을 들고 있는 경우가 많아서, 말로 조건을 넣을 수 있으면 실제로 쓸모가 있거든요."

### Q. AI 도구가 코드를 다 짜준 거 아닌가요?

> "코드 작성에 AI를 썼습니다. 다만 그대로 받아쓰지는 않았습니다.
> 배포가 실패했을 때 로그를 읽고 어느 단계에서 끊겼는지 판단한 것, 404를 보고 '키가 아니라 이름 문제'라고 좁힌 것, 후보 목록 방식도 결국 짐작이라 목록 조회로 바꾼 것 — 이 판단들은 제가 했습니다.
> 그리고 지금 이 흐름을 처음부터 끝까지 설명드릴 수 있습니다."
